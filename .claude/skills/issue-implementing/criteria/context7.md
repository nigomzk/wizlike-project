# Context7の運用

Godotのエンジン仕様に関わる判断は、**記憶や思い込みではなく、公式ドキュメント（Godot 4.5）を根拠にする。** ただし、Context7 は月間の問い合わせ数に上限があるため、**使う場面を限る。** メインエージェント（手順3）、`architecture-reviewer`（手順5）、`code-explainer`（手順8-2）のすべてが従う。

---

## 1. 参照先

| 項目 | 値 |
| --- | --- |
| ライブラリID | `/websites/godotengine_en_4_5`（プロジェクトの Godot 4.5.1 に対応する） |
| 予備 | `/godotengine/godot-docs/__branch__4.5`（上のIDで見つからない場合だけ使う） |
| 使わないもの | 4.6、4.7、`stable` など、ほかの版の資料。版によってAPIや挙動が違うため |

ライブラリIDは固定なので、`resolve-library-id` は使わずに `query-docs` へ直接渡してよい。

---

## 2. 調べる順

1. **確認済みキャッシュを検索する**（3）。見つかれば、その結論と出典を使う。Context7 には問い合わせない
2. 見つからなければ、**4の段階**に従って、Context7 に問い合わせるかを決める
3. 問い合わせたら、結果をキャッシュに追記する（3）

---

## 3. 確認済みキャッシュ

| 項目 | 値 |
| --- | --- |
| 場所 | `.claude/skills/issue-implementing/knowledge/godot-verified.md`（git の管理対象外。Issue をまたいで残る） |
| 検索 | Grep で、確かめたい語（クラス名、メソッド名、概念）を `-i` で探す。1つの語で見つからなければ、別の語（英語の識別子と日本語の両方）でも探してから「なし」とする |
| 追記 | Context7 で確かめたら、1事項ずつ末尾に追記する。ファイルがなければ、下の見出しから作る |
| 版 | Godot 4.5.1 の事項だけを載せる。プロジェクトの版が変わったら、ファイルを削除して作り直す |

形式（1事項を `##` 見出し1つにする）：

```markdown
## <確認した事項。1つの概念>
- 問い合わせ: <query-docs に渡した文>
- 結論: <分かったこと。想定と違った場合はそれも書く>
- 出典: <https://docs.godotengine.org/en/4.5/...>
- 確認: <YYYY-MM-DD>（Issue #<N>）
```

- **根拠が確かなものだけを載せる。** 「未確認」「該当なし」「あとで再確認」の結論は載せない
- キャッシュと食い違う事実が、テストの失敗などで見つかったら、Context7 に1回だけ問い合わせ直し、該当する事項を**書き換える**
- キャッシュは管理対象外で、PRでレビューされない。**誤りが残らないよう、出典URLのない事項は載せない**

---

## 4. 問い合わせる場面（段階）

「迷ったら確認する」としない。次の段階で決める。

### 段階A：実装の前に、必ず確認する（失敗が静かなもの）

テストで気づけない、または気づくのがユーザーの手動確認になってしまうもの。

| 対象 | 例 |
| --- | --- |
| ノードとリソースの挙動 | `_ready` / `_enter_tree` / `_exit_tree` の順序、`queue_free` と `call_deferred` の時機、シグナルの接続と切断・接続フラグ、`Resource` の共有と複製、`SceneTree` の振る舞い |
| プロジェクト設定 | `project.godot` の設定キーと値（表示、ストレッチ、レンダラー、Autoload、入力マップ） |
| インポート | `.import` の設定、インポーターの種類、テクスチャやフォントの扱い |
| コマンドライン | `--headless` / `--script` / `--import` / `--quit` などの引数、`OS.execute`、終了コード |
| UIとテーマ | `Control` のアンカーとサイズフラグ、フォーカスと入力の伝播、`mouse_filter`、`Theme`、`CanvasLayer` |
| ファイル入出力 | `FileAccess` / `DirAccess` / `ConfigFile`、`user://` の解決、renameの挙動 |
| 言語仕様のうち、意味が静かに変わるもの | ラムダが外側の変数を取り込む方法、`await` の再開時機 |

### 段階B：先に書いてテストを実行し、直せないときに確認する（失敗が大きな音で出るもの）

存在しないメソッドや、誤った引数・戻り値の型は、パースエラーか実行時エラーとして、テストの実行で必ず現れる。

| 対象 | 例 |
| --- | --- |
| エンジンのAPI | メソッドの有無、シグネチャ、戻り値、引数の既定値、使えるクラス |
| 言語仕様の構文 | 静的型付け、`class_name` と Autoload の名前の衝突、`@export` / `@onready`、型付きの配列と辞書の宣言 |

- エラーメッセージを読んで直せるなら、確認しない
- **同じ箇所を1回直しても直らない**場合に、Context7 に問い合わせる
- 確認したら、キャッシュに追記する

### 段階C：確認しない

`Array.append`、`Dictionary.get`、`String.format`、四則演算、`for` / `match` の基本構文のように、版による違いがなく、誤用しても直後のテストで必ず分かるもの。

### 判断に迷うとき

段階Aの対象に当たるかどうかだけで決める。「不安かどうか」では決めない。段階Aの表に当たらず、迷うものは段階Bとして扱う。

---

## 5. 問い合わせの手順

1. 確認したい概念を**1つに絞って**問い合わせる。複数の概念を1回に混ぜない
2. 問い合わせ文に、プロジェクトのコードや固有名、秘密情報を含めない。一般的な概念として尋ねる（例：「Autoload の名前と同じ class_name を持つスクリプトの扱い」）
3. 結果の出典URL（`docs.godotengine.org/en/4.5/...`）を確認する。4.5 以外の版のURLは根拠にしない
4. 結論を、キャッシュ（3）に追記し、`templates/context7-log.md` の形で調査ログにも記録する

---

## 6. 結果の扱い

| 状況 | 扱い |
| --- | --- |
| ドキュメントと自分の想定が食い違った | **ドキュメントに従う。** 想定していた書き方を採らない |
| ドキュメントに記述が見つからない（3回問い合わせても該当なし） | 「未確認」として記録する（キャッシュには載せない）。メインエージェントは、その判断をテストで裏付けられるならテストで確かめ、そうでなければPR本文の「未確認の事項」に載せる |
| Context7が使えない（接続エラー、月間の問い合わせ上限など） | 推測で進めない。使えなかったことを記録し、該当する判断を「未確認」としてPR本文に載せる。上限に達した場合は、以降の問い合わせを試みない。レビュー担当にも、packet.md の申し送りで上限に達したことを伝える。**キャッシュにある事項は、上限に達していても使える** |
| 技術設計の文書とドキュメントが矛盾する | 実装を止め、矛盾の内容を提示して判断を仰ぐ |

---

## 7. 問い合わせの上限

1つの作業での問い合わせ件数に、次の上限を置く。キャッシュの検索は数えない。

| 担当 | 上限 | 超えるとき |
| --- | --- | --- |
| `architecture-reviewer` | 1ラウンドに8件 | 上限を超える分は「未確認」とし、指摘は should 以下にする |
| `code-explainer` | 1サイクルに12件 | 上限を超える分は `unverified: true` にする。**エンジン固有の事項を、言語の基本より先に確認する** |
| メインエージェント | 上限なし | 段階Aに当たる判断だけを問い合わせる。1つの Issue で15件を超えたら、判断の洗い出しを見直す |

---

## 8. レビューでの扱い（architecture-reviewer）

- Godotに関わる指摘には、根拠欄に**出典URL**を書く
- ドキュメントで裏付けられない指摘は **must にしない。** 重大度は should 以下にし、指摘内容に「未確認」と明記する
- **調査ログとキャッシュに記録がある事項は、再び問い合わせない。** 記録の出典が、そのコードの使い方を裏付けているかを、記録の文面だけで読んで判断する
- 段階Aの対象に当たるのに、調査ログにもキャッシュにも記録がないままのコードは、**自分で問い合わせて確かめる**（7の上限の範囲で）。誤用なら must、正しいが記録がないだけなら should とする
- 段階Bの対象は、テストが通っていれば問い合わせない。記録がなくても指摘しない
