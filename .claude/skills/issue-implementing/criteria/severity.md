# 重大度の判定基準

レビュー担当は、すべての指摘に重大度を1つ付ける。**重大度ごとに、必要な根拠の種類が決まっている。** 必要な根拠を示せない指摘は、1段階下げる。

---

## 1. 重大度

| 重大度 | 意味 | 当てはまる例 |
| --- | --- | --- |
| must | 規則・Issue・DoDに反している。このままではIssueを完了にできない | ・仕様根拠の規則IDを満たしていない、または逸脱している<br>・DoDの受入IDが検証されていない、失敗している、またはスキップのまま成功扱いになっている<br>・「壊してはいけないもの」の受入IDが落ちる<br>・数値の直書き（`data/` を正とする原則に反する）、設計書にない要素の追加、推測による仕様の補完<br>・Issueの「タスク」に明記された指示に反している（期待値の直書き、指定されたファイルパスとの不一致など）<br>・Godotのドキュメントで誤用と確認できるAPIの使い方<br>・画面文書の表示・遷移・キー割り当て・入力の遮断・文言に反している<br>・クラッシュ、データの破損、入力の取りこぼしにつながる不具合 |
| should | 規則には反していないが、設計規約からずれている、または保守上の問題がある | ・技術設計の規約（構成・責務・データモデル・表示）からのずれ。動作は正しい<br>・責務の置き場所が不適切（ルール層に描画の都合が入っているなど）<br>・テストが脆い（実行順に依存する、乱数の系列を固定していないなど）<br>・確認が必須のAPIを、調査ログに記録しないまま使っている<br>・Godotの挙動についての懸念で、ドキュメントで裏付けられないもの（「未確認」と明記する） |
| nit | 好みや表記の問題。直さなくても品質に影響しない | 命名、コメントの文言、空行、並び順 |

---

## 2. 必要な根拠

| 重大度 | 必要な根拠（どれか1つ以上） |
| --- | --- |
| must | 規則ID / 受入ID / Issueの節と記述 / Context7の出典URL（`docs.godotengine.org/en/4.5/...`）。**いずれの場合も、違反している箇所の `file:line` を添える** |
| should | 技術設計の規則ID / Context7の出典URL / 問題を具体的に示す `file:line` と、その理由 |
| nit | `file:line` |

「一般的にはこう書く」「〜のほうが良いと思う」だけでは根拠にならない。

規則IDは、レビューのたびに `docs/index.md` から辿った**現在の設計書**で確かめてから書く。記憶している番号や、このスキルの文書に書かれた例を根拠にしない。

---

## 3. 判定

| 判定 | 条件 |
| --- | --- |
| 承認 | must が0件 |
| 要修正 | must が1件以上 |
| 該当なし | 自分の担当の観点に関わる変更がない |

should と nit だけの場合は「承認」とする。メインエージェントは「承認」であっても、should をIssueの範囲内で修正することがある（`finding-triage.md`）。
