# レビュー依頼の材料（packet.md）の型

手順5-1で、`scripts/make-packet.mjs make` が `cycle-<c>/round-<r>/packet.md` として骨組みを書き出す。レビュー担当はこのファイルから読み始める。メインエージェントが埋めるのは、「（要記入）」の箇所だけである。書き終えたら `make-packet.mjs check` で、「（要記入）」が残っていないことを確かめる。該当しない節は「なし」と書かれ、節は削られない。

下の例は、スクリプトが書き出す形である。

---

```markdown
# レビュー依頼：Issue #<N> サイクル<c> ラウンド<r>

## 対象

| 項目 | 値 |
| --- | --- |
| Issue | #<N> <タイトル> |
| ラベル | <area:..., type:...> |
| モード | 初回 / レビュー対応 |
| ブランチ | <{type}/{N}-{slug}> |
| 比較 | origin/main...HEAD（<HEADの短いハッシュ>） |
| 起動したレビュー担当 | <--reviewers に渡した文。起動しなかった担当と理由も書く> |
| 確認の範囲 | 全体（1ラウンド目） / 前ラウンドの修正のみ（2ラウンド目以降） |

## 材料

**材料のフォルダ（絶対パス）：** `<.../cycle-<c>/round-<r>>`

下の相対パスは、このフォルダからのもの。

| 材料 | 相対パス |
| --- | --- |
| Issue本文 | issue.md |
| 差分 | diff.patch |
| 前ラウンドからの差分（2ラウンド目以降） | diff-since-prev.patch |
| 前ラウンドの処置表（2ラウンド目以降） | ../round-<r-1>/triage.md |
| **規則IDと受入IDの原文** | rules-excerpt.md（設計書を開き直さず、まずここを読む） |
| ID一覧の下書き | id-table.md |
| テスト：先に書いたとき | ../test-red.log |
| テスト：実装後 | ../test-green.log |
| テスト：このラウンドの直前 | test-latest.log |
| Context7の調査ログ | ../../context7-log.md |
| 出力の型・重大度の基準・Context7の運用 | .claude/skills/issue-implementing/ 配下（リポジトリ内） |

## 変更ファイル

| ファイル | 変更の種類 | 対応するタスク（2ラウンド目以降は対応する指摘） |
| --- | --- | --- |
| <path> | 追加 / 変更 / 削除 / 改名 | （要記入） |

## テストの実行条件

| 実行 | 指定した受入ID | 終了コード |
| --- | --- | --- |
| 先に書いたとき（1ラウンド目） | <--red-ids> | <ログの exit=> |
| このラウンドの直前 | <--latest-ids> | <ログの exit=> |
| 全体（受入IDの指定なし） | — | <test-all.log の exit=> |

## 手動確認の対象（手動確認の受入ID）

- <ID>（DoD / 壊してはいけない）：（要記入。確認する内容。ユーザーが手順10で実施する）

## メインエージェントからの申し送り

- （要記入。判断に迷った点、Context7で「未確認」とした点、Issueと設計書の解釈で選んだ点）

## 前のラウンドの指摘の処置

<ラウンド2以降は、前ラウンドの triage.md の内容。1ラウンド目は「なし（1ラウンド目）」>

## ユーザーの指摘（レビュー対応モードのみ）

<--user-findings に渡したファイルの内容。なければ「なし」>
```
