# レビュー担当の出力の型

4体のレビュー担当は、次の順に出力する。

1. **担当ごとの表**：各エージェントの定義（`.claude/agents/*-reviewer.md`）の「出力の形」に従う
2. **共通の指摘表**：下の形
3. **判定**：下の形

---

## 共通の指摘表

```markdown
## 指摘

| 指摘ID | 重大度 | 根拠 | 指摘内容 | 修正案 |
| --- | --- | --- | --- | --- |
| <接頭辞>-01 | must / should / nit | <規則ID・受入ID・Issueの節・Context7の出典URL> ／ <file:line> | <何が、どう問題か。1〜2文> | <どう直すか。1〜2文> |
```

| 列 | 書き方 |
| --- | --- |
| 指摘ID | エージェントごとの接頭辞＋2桁の連番。`SPEC-01`（spec-conformance-reviewer）、`TEST-01`（test-reviewer）、`ARCH-01`（architecture-reviewer）、`SCRN-01`（screen-reviewer）。ラウンドをまたいで番号を振り直してよい |
| 重大度 | `criteria/severity.md` に従う |
| 根拠 | 重大度に必要な根拠の種類を満たす。`file:line` は差分の中の位置ではなく、リポジトリ上の位置で書く。ID一覧の下書きへの指摘は `id-table.md:<行>` と書く |
| 指摘内容 | 事実と、それが根拠に反する理由。推測で書く場合は「未確認」と明記する |
| 修正案 | 具体的に。Issueの範囲を超える修正が必要な場合は、そう書く |

指摘がない場合は、表の代わりに「指摘なし」と1行だけ書く。

---

## 判定

```markdown
## 判定

**承認** / **要修正** / **該当なし**

- must <n>件、should <n>件、nit <n>件
- <判定の理由を1文。該当なしの場合は、担当の観点に関わる変更がないこと>
```
