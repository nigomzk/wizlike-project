# テスト基盤

テストの実行方法、注入点、IDの索引を定義する。**個々の受け入れ条件は各仕様文書に置く。** 本文書に条件の内容を複写しない。

---

## 1. 実行（TST-0xx）

| ID | 規則 |
| --- | --- |
| TST-000 | ルールの境界はヘッドレスのGDScriptテストで検証する。描画・入力は画面ごとの手動確認（U）、配布と通しのプレイはWindows実機（W）で検証する。 |
| TST-001 | テストの入口を `godot --headless --path . --script tests/run_all.gd` とする。 |
| TST-002 | `run_all.gd` は `SceneTree` を継承し、全テストの完了後に終了コードを指定して `quit()` する。 |
| TST-003 | 失敗が1件でもあれば終了コードを非0とする。スキップは失敗に数えない（TST-006）。 |
| TST-004 | 失敗したテストのID、期待値、実測値を標準出力へ出力する。 |
| TST-005 | テストはGodotエディターを起動せずに完了する。 |
| TST-006 | `run_all.gd` は `--require=<受入ID,...>` を受け付ける。指定したIDが成功以外（失敗またはスキップ）であれば終了コードを非0とする。段階とIssueの完了判定には、その範囲の受入IDを指定して実行する。 |
| TST-007 | テストファイルの `run()` の実行中に、スクリプトの実行時エラー（`run()` から呼んだ補助関数の中を含む）が起きた場合、そのファイルの `IDS` のうち、明示的に `skip()` されたもの以外をすべて失敗とする。打ち切りの前に `check` が成功していたIDも失敗とし、実行されなかったIDを未実装のスキップ（TST-410）にしない。失敗は TST-003 に従い `--require` の有無に関わらず終了コードを非0とし、失敗したIDと打ち切りがあったファイルを TST-004 に従い標準出力へ出力する。対象はスクリプトの実行時エラーのみとし、`push_error` と `push_warning` は対象外とする。打ち切られたファイルは、ほかのファイルの判定を止めない。 |

## 2. 注入点（TST-1xx）

| ID | 規則 |
| --- | --- |
| TST-100 | テスト用のseed、固定ダメージ倍率、模擬的な保存障害は、テスト専用の注入点から与える。 |
| TST-101 | 本番ビルドにチート用のUIを設けない。 |
| TST-102 | 乱数は `RngService` 経由で取得する。テストでは系列ごとに固定seedを注入できる（ARC-404）。 |
| TST-103 | ダメージ倍率 `r`（BTL-017）を1.0に固定できる注入点を設ける。 |
| TST-104 | 命中判定を常に成功または常に失敗に固定できる注入点を設ける。 |
| TST-105 | `.tmp` の書込み、`.bak` への退避、renameのそれぞれに失敗を注入できる点を設ける（SAV-3xx）。 |
| TST-106 | アプリの終了要求を差し替えられる点を設ける。テストでTITLEの「終了」を、ランナーを止めずに判定するため。 |
| TST-107 | 設定ファイルとセーブの置き場所（`user://` 配下）を差し替えられる点を設ける。テストが開発者の実際の設定とスロットを変更しないため。 |
| TST-108 | `GameDatabase.load_and_validate()` の読込元ディレクトリとログの出力先を差し替えられる点を設ける（D03）。 |
| TST-109 | `run_all.gd` は `--files=<res://パス,...>` を受け付け、実行するテストファイルの一覧を差し替えられる。T01〜T04が、フィクスチャだけを子プロセスのGodotで実行するために用いる。指定しない場合は TST-400〜409 の全ファイルを実行する。 |

## 3. IDの命名（TST-2xx）

| ID | 規則 |
| --- | --- |
| TST-200 | 受け入れ条件のIDは `英字1〜2文字 + 2桁の連番` とする。文書をまたいで一意とする（GLS-003）。 |
| TST-201 | IDを一度割り当てたら再利用しない。削除した場合は欠番とする。番号の詰め直しや付け替え（再採番）もしない（GLS-004）。 |
| TST-202 | 新しい条件を追加する場合、対応する規則がある文書に追記し、下の索引を更新する。 |

## 5. テストファイルの分割（TST-4xx）

| ID | ファイル | 担当する接頭辞 |
| --- | --- | --- |
| TST-400 | `tests/test_maps.gd` | D |
| TST-401 | `tests/test_growth.gd` | G, L, P |
| TST-402 | `tests/test_inventory.gd` | I |
| TST-403 | `tests/test_battle.gd` | B |
| TST-404 | `tests/test_save.gd` | S |
| TST-405 | `tests/test_facility.gd` | F, Q |
| TST-406 | `tests/test_flow.gd` | FL |
| TST-407 | `tests/test_exploration.gd` | E |
| TST-408 | `tests/test_runner.gd` | T |
| TST-409 | `tests/test_core.gd` | A |

| ID | 規則 |
| --- | --- |
| TST-410 | 各テストファイルは、担当する接頭辞のIDをすべて実装する。未実装のIDは明示的にスキップとして報告し、成功として数えない。 |
| TST-411 | 未実装のテストと未実施のテストを完了として扱わない（SCP-402）。 |
| TST-412 | ランナーの検証（T01〜T04）に用いるフィクスチャのテストファイルは `tests/fixtures/` に置く。フィクスチャは TST-400〜409 の担当ファイルではなく、`--files=`（TST-109）で指定されたときだけ実行される。受入IDの索引（§4）には含めない。 |
| TST-413 | 各テストファイルは `extends RefCounted` とし、担当するIDを列挙する `const IDS` と、`func run(t)` を持つ。`t` は `check(id, expected, actual)` と `skip(id, reason)` を提供する。`run()` が実行時エラーで打ち切られた場合の扱いは TST-007 に従う。 |

## 6. 受け入れ条件

ランナー自体の検証は、フィクスチャのテストを子プロセスのGodotで実行させて判定する。

| ID | 前提・操作 | 合格条件 | 根拠 |
| --- | --- | --- | --- |
| T01 | 全件が成功するフィクスチャを実行する | 終了コードが0。エディターを起動しない | TST-002, 003, 005 |
| T02 | 1件だけ失敗するフィクスチャを実行する | 終了コードが非0。失敗したテストのID、期待値、実測値が標準出力に出る | TST-003, 004 |
| T03 | スキップを含むフィクスチャを、`--require` なしと、スキップしたIDを `--require` に指定して実行する | スキップは成功件数に数えられず一覧で報告される。前者の終了コードは0、後者は非0 | TST-006, 410, 411 |
| T04 | 実行時エラーで打ち切られるフィクスチャを、`run()` 直下で打ち切られるものと、`run()` から呼んだ補助関数の中で打ち切られるもの（`run()` は最後まで到達する）の2種類用意し、それぞれを `--require` ありとなしで実行する。また、打ち切られるフィクスチャと、IDSが重複しない完走フィクスチャを同時に `--files=` で指定して実行する。さらに、`skip()` したあとに打ち切られるフィクスチャと、`push_error` と `push_warning` を出して完走するフィクスチャを、それぞれ実行する | 終了コードが非0（0でも -1 でもない）。出力に失敗したIDと打ち切りがあった旨が出る。打ち切られたファイルのIDはいずれも成功に数えられない（`SUMMARY` の `passed` に含まれない）。完走フィクスチャのIDは成功として数えられる。実行時エラーの後も `SUMMARY` まで出力して終了する。`skip()` したIDはスキップのままで、ほかのIDは失敗になる。`push_error` と `push_warning` だけを出すフィクスチャは、終了コードが0で、打ち切りの出力がなく、成功として数えられる | TST-003, 006, 007 |
