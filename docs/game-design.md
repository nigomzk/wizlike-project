## 1. 目的と進め方

GodotとGDScriptで、簡単な世界樹の迷宮ライクなRPGを制作する。他のAIエージェントが追加の仕様判断なしに実装できる粒度の設計書を完成させる。

質問は依存関係のある設計ツリーとして整理する。各ラウンドで回答を記録し、そこから確定できる仕様と次の質問を更新する。提案はユーザーの回答まで確定扱いにしない。最終的に仕様・受け入れ条件を確認し、共有認識の合意を得る。本セッションの対象は設計書作成であり、ゲーム実装ではない。

## 2. ユーザー指定の要件

### 基盤・街

- エンジン：Godot 4.5.1 Standard。同版Export Templatesを使用する。
- 言語：GDScript。
- ジャンル：RPG。
- 対象：Windows 11、キーボード＋マウス、日本語、1人プレイ。
- タイトル画面に「はじめから」「つづきから」を設ける。「つづきから」は複数のセーブスロットから選んでロードする。
- セーブは街での手動操作のみ、5スロット。オートセーブなし。上書き前に確認し、「はじめから」の選択だけでは既存データを消さない。
- 街は2Dで背景に街の1枚絵を表示する。
- ギルド：冒険者登録、キャラクター作成、パーティ編成、訓練場でのスキル習得。
- 教会：状態異常の治療、死亡キャラクターの蘇生。
- 商店：道具・武器・防具の売買。
- 宿屋：回復。
- 酒場：クエストの受領・報告。

### ダンジョン

- 各フロアは30×30マスの2Dマップ。ユーザーの視界は3D。
- 制作者が2DのTileMapでマップを定義し、自動で3Dへ変換する方式を想定。
- ミニマップを表示できるようにする。
- 階段の上り下りでフロアを移動する。
- ダンジョンの最終フロアにボスを配置する。
- ボスの先の道から次のダンジョンへ進む構成を想定。
- 初回版は2ダンジョン×各3フロア。第1ダンジョンのボスの先から第2へ進み、第2ダンジョンの最終ボス撃破でゲームクリア。
- 一人称で1マスずつ前後・左右に移動する。左右移動では向きを変えない。旋回は90度単位。自由移動・自由視点は設けない。
- ミニマップは歩いた場所を自動記録する。未踏破を隠し、踏破済みの床・周囲の壁・発見した階段等を表示する。手描き機能は設けない。
- 街から1Fまたは中間地点へ移動する。
- 1Fの出口、帰還アイテム、中間地点のワープから街へ帰還する。
- 第1ダンジョンには中間地点を設けない。第2ダンジョン1Fの入口付近に魔法陣型の中間地点を1か所設ける。
- 未起動の魔法陣に乗ると起動するか選択肢を表示する。一度起動すると利用可能になる。第2ラウンド以前の「各2Fのワープ」「第2ダンジョン初到達だけで街の出発先に追加」という提案は採用しない。
- 魔法陣の起動・往復は無料で回数制限なし。起動を断った場合は再訪時に再確認する。起動時に街の出発先へ追加し、「街へ戻る／留まる」を選択する。起動後も乗ると帰還確認を表示する。帰還アイテムは探索中のみ使用可能。
- ラスボス以外のボスは撃破からゲーム内30日経過すると復活する。宿泊1回で1日進み、他の行動・救済回復・現実時間では進まない。各撃破日を保存し、30日後から初回と同じ強さ・経験値・お金・抽選ドロップで再戦可能。宝箱・クエスト・初回イベント報酬は復活しない。
- 復活ボスのマスに徒歩で入ると再戦する。初回撃破による通路開放と魔法陣起動は維持し、街から起動済み魔法陣への移動では再戦不要。日数は期限ではなく再出現の管理に使用する。
- 実装エージェントが6フロアの仮マップを用意し、開始からクリアまで検証可能にする。その後ユーザーがTileMapで地形・配置を編集する。設計書でタイル・イベント・接続の制作規約を定める。
- 初回版の仕掛け：扉・宝箱・調べるイベント・ワープ・ボス・片側から開通する近道。徘徊強敵・落とし穴・移動床は設けない。

### キャラクター・成長

- パーティは1〜4人。編成は街のギルドで行う。
- 冒険者登録は無料、最大20人、同職業の重複可。初期編成は自分で作る。難易度は4人基準で固定し、少人数でも敵を弱体化しない。
- 新規登録者はレベル1・初期スキル習得済み・HP/SP満タン。職業ごとに装備できる最低ランクの武器と、全職業共通の低ランク防具（布の服など）を初期装備として支給する。初期装備の売値は低く設定する。
- 初期のお金・消耗品はニューゲーム時に一度だけ共有資産へ支給する。装備はニューゲーム時の一括支給ではなく、冒険者の登録ごとに支給する。
- ギルドで冒険者を登録する際、名前・職業・見た目をカスタマイズする。
- 初回版の職業：戦士・騎士・魔術師・僧侶・斥候の5種類。武士・忍は初回版には含めない。
- 見た目は用意された顔画像または立ち絵から選択する。探索中の味方3Dモデルは設けない。初回版は仮素材を許容し、差し替え可能な構成にする。
- 職業によって初期パラメータと成長しやすいパラメータが異なる。
- 職業の役割：戦士＝物理攻撃、騎士＝防御・かばう、魔術師＝属性攻撃、僧侶＝回復・蘇生、斥候＝高速行動・探索支援。前衛・後衛の隊列は設けない。
- 基礎パラメータ：HP、SP、STR、VIT、TEC、AGI、LUC。
- HPが0になると死亡する。キャラロストはない。
- 攻撃力＝STR＋武器の攻撃力。
- 守備力＝VIT＋防具の防御力。
- TECは命中率など、AGIは行動順・回避率、LUCは状態異常付与成功率などに影響する。
- 戦闘勝利後、経験値が条件を満たすとその場でレベルアップする。
- 成長はランダムで、職業補正がある。
- レベル上限は20。成長量は固定増加＋職業別ランダム加算。戦闘経験値は生存している戦闘参加者に均等配分し、死亡者・待機者には与えない。
- レベルアップ時は最大HP/SPの増加分だけ現在HP/SPも増加させる。全回復はしない。
- スキルはギルドの訓練場でお金を払って習得する。習得可否は職業とレベルで決まる。
- 強力なスキルほど要求レベル・習得料金・消費SPが高い。
- 死亡は蘇生スキルまたは教会で回復する。
- 各職業に初期スキル1個を用意する。スキルのランクアップ・転職は設けない。

### 探索資源・装備・クエスト

- 探索資源はHP・SP・消耗品・所持品の空き枠。満腹度・装備耐久・時間制限は設けない。
- 歩行によるHP・SPの自然回復なし。戦闘終了時もHP・SPの消耗、死亡、毒が残る。
- 探索中はメニューから回復・解毒・蘇生スキルと対応アイテムを使用可能。戦闘専用スキルは使用不可。
- 宿屋は生存者のHP/SPを全回復し、蘇生・解毒は教会が行う。両施設は待機中の冒険者にも利用可能。
- 通常料金を払えない場合の救済として、所持金全額を使い全登録者を蘇生・解毒・HP/SP全回復する選択肢を設ける。所持金0でも利用可能、借金なし。判定対象の料金など具体的な条件はgameplay-spec.mdの施設仕様に従う。
- 装備は武器・防具・装飾品の3枠。職業による装備制限あり。
- 所持品はパーティ共通30枠。同種消耗品は1枠9個、装備品は1個1枠。装備中の品は枠に数えず、進行上の重要品は別管理する。
- 任意の討伐・納品クエストを合計6件用意する。必須進行条件はボス撃破であり、クエスト完了は必須にしない。
- クエスト報酬は経験値・お金・アイテム。クリアすると冒険が少し楽になる補助要素とする。
- 各クエストは一度のみ完了可能。討伐は受注後から計数し、納品は受注前の所持品も使用可能。酒場で報告時に報酬を受領する。経験値は報告時の生存パーティメンバーで均等配分し、待機者・死亡者には与えない。クエスト経験値でも即時レベルアップする。
- 物語は短い導入と施設・ボス前後のテキスト会話を中心とする。
- クリア後は街へ戻り探索継続可能。周回機能・追加ダンジョンは設けない。

### 戦闘・ゲームループ

- 一定歩数を基準にランダムな歩数でエンカウントする。
- 戦闘はターン制。
- 生存している味方全員のコマンドを選択後、敵味方が行動順に実行する。
- コマンドは通常攻撃・スキル・防御・アイテム・逃走。通常戦は逃走可能、ボス戦は不可。敵は2D画像で表示する。
- 攻撃属性は物理・火・氷・雷。弱点・耐性あり。状態異常は毒・麻痺・睡眠、加えて死亡を扱う。
- 毒のみ戦闘後も残り、歩行時にダメージを受ける。歩行毒ではHPが1未満にならない。
- 勝利報酬：経験値、お金、一定確率のアイテムドロップ。
- 全員死亡するとゲームオーバー。
- 全滅後はタイトル画面に戻る。再開する場合は「つづきから」でセーブデータをロードする。自動的な街への復活は行わない。
- 基本ループ：街で準備→ダンジョンへ出発→探索→戦闘→報酬・成長→探索を継続または街へ帰還。
- 面白さの優先順位：第1は限られたHP・SPで進むか帰還するかを判断する探索、第2は編成と戦闘攻略。

## 3. 表記の確認事項

- スキル消費資源の名称はSPに統一する。元のゲームフロー中のTPもSPを指す。
- 「2Dマップ」は制作用データとプレイヤー向けミニマップを区別する。ミニマップは自動記録とする。
